# Room Echo 两分钟演示脚本

使用同域的默认单页养老模拟演示：

```bash
make submission-demo PORT=8000
# http://127.0.0.1:8000/#/home
```

默认 `#/home` 一次加载完整 `simulated-care-scenario.v2`，从日常开始，每 8 秒自动循环日常、卫生间超时、人工跌倒演练和夜间宠物外部标签；不切页、不改 URL、不重复请求。演示只依赖首页现有信息、Memory 原有回放结构和 Why 原有解释结构，不依赖场景选择器、人物/户型卡、全天时间线或额外来源模块。它是 Mock 工作流展示，不是 Live 或真实照护证明。

## 演示时必须说清楚

- 部署后的公开链接默认 Home 是确定性 Mock 养老工作流演示，不是 Live 硬件或真实照护证明。
- 右侧是艺术化代理信号推断场，不是摄像图像、人体轮廓或现场空间重建。
- 四个反应 tile 只表达同一 Agent 的模拟预览或暂缓状态；没有真实设备执行、消息发送或 ACK。
- 前台一个 Agent，内部七角色只用于 audit；解释一致度与传感置信保持分离。
- 证据不足时展示 unknown/withheld，而不是生成更大胆的故事。
- 默认 `#/home` 一次加载完整 care v2 场景并每 8 秒循环；`?care=...` 只选择初始帧。人物、户型、日程、宠物和跌倒字段仍是 synthetic / external / drill fixture，主演示不在前端展开这些资料。
- 左 Agent、四行动与右场引用同一 hash-bound Mock `proxy_triplet`；这证明界面连通性，不证明真实养老检测精度。

## 可复现检查

1. 开场确认首页只有品牌、三个导航、一个 Agent 卡、2×2 四反应 tile 和右侧中心形态；不存在额外 care 信息模块。
2. 确认右侧外围循环数字已移除，中心彩色数字形态仍实时运动，非摄像水印仍在。
3. 等待至少一次 8 秒自动切换，确认 URL 未改变、care API 未重复请求，Agent/四格/右场的 evidence/session/window 同时变化且保持一致。
4. 确认四格状态只可能 `simulated_preview` / `withheld`，不存在 executed/completed；至少一个现有数字形态作为反应图标。
5. 打开 Memory 与 Why，确认只统一毛玻璃材质，原有信息架构没有被 care fixture 替换。
6. 断开数据、注入 malformed 响应或进入 degraded/unavailable，确认旧解释被清除、数字场停止信号驱动动画、四行动保持 withheld，且没有 Replay 数据泄漏。
