## 一、作品名称与一句话

### 作品名称

**空间回声 Room Echo**

### 作品副标题

**一个不拍下你、会解释变化、也知道何时保持沉默的空间 Agent**

### 一句话介绍

空间回声把经校准的 Wi-Fi 变化转成活动强度、遮挡／空间占用代理和相对纵深代理，再由一个用户可见的 Agent 实时解释变化、呈现受限行动，并在证据不足时明确保持未知。

### 30 秒作品介绍

空间回声 Room Echo 是从创作者 J 的真实需要出发制作的隐私优先空间 Agent。J 长时间在小型空间进行 AI 与视觉创作，希望保留空间节奏的变化，却不愿让摄像头持续记录自己。复赛候选版本使用明确标注的 Replay，把 Wi-Fi 变化转成三个克制的代理信号；前台只出现一个 Room Echo Agent，左侧解释“我观察到什么、如何理解、还不知道什么”，底部行动窗口只展示“保持静默、继续观察或环境光模拟预演”。内部多视角与怀疑者只负责反证和审计，不抬高传感置信。下一 MVP 将验证这套低侵入、分级介入的能力是否适合原居养老，但当前还没有养老用户验证，也没有真实灯光或照护服务执行记录。

### 完整作品介绍

空间回声 Room Echo 是一套隐私优先的环境具身智能原型。它不调用摄像头，也不试图识别身份、人数、姿态或健康状态，而是把经校准的 Wi-Fi CSI 变化转译成三个有限代理信号：活动强度、相对空场基线的遮挡／空间占用代理，以及沿已标定轴的近／中／远相对纵深代理。

复赛候选版让用户看到的不是多个 Agent 开会，而是一个持续存在的 Room Echo Agent。它在左侧用第一人称说明当前证据、变化趋势、替代解释和不确定性；底部行动窗口只呈现一项当前反应及其状态。右侧保留现有的彩色数字推断场／数字轮廓，动画继续只由三个代理信号和质量驱动。数字轮廓是可视隐喻，不是被感知者的影像、身体或姿态。内部的多视角解释、怀疑者复核和确定性 Policy 仍在后台运行，用来阻止越权结论；Agent 不能改写测量或抬高置信度。

复赛候选版本已用封存 Replay 展示完整链路，并把环境光模拟行动明确标为 `SIMULATED PREVIEW`；公网运行提交 `76c71b1` 已完成健康、桌面与手机复验。下一 MVP 是 Room Echo Care：面向排斥家庭摄像头、但希望获得低风险空间辅助的原居老人、家属与照护服务方，验证夜间预设灯区、轻量确认和真人接管的分级闭环。Care 目前是待验证方向，不是已经被养老用户使用过的产品。

## 二、需求起点人物与目标用户

### 需求起点人物：J

J 是一位在北京进行 AI 与视觉创作的创作者，也是本项目的创作者和界面体验者。J 已确认以下描述符合自己的真实经历，并同意以代称 J 用于报名、PPT、演示视频和作品展示：

> 我长时间在小型空间进行 AI 与视觉创作，希望保留空间节奏的变化，但不希望摄像头持续记录我。

J 的需要不是“看见房间里是谁”，而是：

- 不留下清晰影像；
- 仍能感知空间节奏正在发生变化；
- 能回看一个值得记住的空间时刻；
- 能理解 Agent 为什么这样回应；
- 证据不足时，系统愿意说不知道。

### 当前作品的直接目标用户

- 不愿被摄像头持续记录的独立创作者；
- 居家工作者、排练者和小型工作室使用者；
- 希望保存空间节奏、但不需要身份或行为识别的人。

### 下一 MVP 的目标用户假设：Room Echo Care

下一 MVP 拟面向：基本能够自理、独居或白天独处、排斥家庭摄像头，并希望获得低风险环境辅助的老年人。家属、社区、养老机构和家庭养老床位运营方是可能的协作与服务角色。

这部分目前只有产品定位与场景假设，**没有目标老人、家属或照护运营方的真实使用反馈**。在完成目标用户访谈、体验、匿名授权与二次复验前，不能把 Care 写成已验证需求。

## 三、真实需要与具体使用场景

### 当前已验证的真实需要

摄像头会留下清晰影像，普通人体传感器通常只给一个简单状态，通用聊天助手又无法持续接触空间变化。J 需要的是一种低侵入、可回看、会承认不确定性的空间反馈，而不是更强的监控。

### 复赛候选版本的体验场景

1. J 打开公开 Replay，看到同一份封存空间记录持续播放。
2. 右侧推断场随活动、遮挡／空间占用代理、相对纵深和质量实时变化。
3. 左侧唯一的 Room Echo Agent 持续说明当前变化与不确定性。
4. 底部行动窗口显示当前反应：保持静默、继续观察，或明确标注的环境光模拟预演。
5. 当质量不足或替代解释未排除时，Agent 显示未知或暂缓，不用语言掩盖证据缺口。

以上单一 Agent 与行动窗口已随运行提交 `76c71b1` 部署并完成公网桌面与手机复验；J 的二次体验仍待确认。

### 下一 MVP 的第一场景：夜间预设灯区辅助

```text
夜间出现活动变化
→ 结合时间、质量和沿已标定轴的粗粒度纵深趋势
→ Policy 判断是否允许低风险响应
→ 预设灯区按规则展开
→ 获取设备回执和用户接受／拒绝
→ 下一次调整是否介入
```

当前作品只能在推断场中展示一个不带“夜间、路径或人物”判断的**通用环境光模拟预演**，不能展示上述完整照护闭环。现有三代理信号不能还原完整户型或识别真实行走路线，因此不得称为“识别路径”；在没有真实灯具回执时，也不得称为“已经亮灯”。

### 下一 MVP 的第二场景：异常模式后的轻量确认

```text
快速变化后持续低活动
→ Wi-Fi 与其他低侵入传感交叉复核
→ 先发出轻量确认
→ 用户通过触摸、语音或实体设备回应
→ 只有在授权、多源复核和无回应条件同时满足时才交给真人
```

这一场景不能称为“跌倒检测”。当前系统不判断健康或危险行为，也尚未连接真实确认设备、照护人员或服务网络。

## 四、单一 Agent 的核心能力与使用流程

### 用户只看到一个 Agent

用户界面只显示 **Room Echo**。原有的多视角角色、怀疑者和综合过程保留在后台，用于反证、Policy 检查与审计，不再成为首页主角。

左侧实时解释固定回答四个问题：

1. **我观察到什么**：只复述当前三个代理信号和质量。
2. **我如何理解**：给出受限解释，不把代理信号升级成身份、人数或行为事实。
3. **我还不知道什么**：主动列出干扰、标定、单 RX 或证据不足。
4. **我为什么这样行动**：说明本轮是保持静默、继续观察，还是环境光模拟预演。

底部行动窗口一次只展示一个动作：

- 保持静默；
- 继续观察；
- 证据不足，暂不行动；
- `SIMULATED PREVIEW`：环境光反应。

保存空间书签仍是用户主动操作，不属于当前行动合约；轻量确认、真人通知和设备执行属于下一 MVP。

### 完整工作流

```text
Wi-Fi CSI／Mock／Replay
→ 确定性三代理信号与质量
→ 封存 EvidencePacket
→ 后台多视角解释与怀疑者复核
→ 确定性 Policy 限制越权和行动等级
→ 单一 Room Echo 解释
→ 行动建议／模拟预演／明确暂缓
→ 设备回执或用户反馈（下一 MVP）
→ 下一周期连续性
```

### 五条不可破坏的规则

1. 实时信号和动画不等待大模型。
2. Agent 只读取紧凑证据，不读取原始 CSI 数组。
3. 多个 Agent 的一致不等于传感器更确定。
4. `final_claim_confidence <= sensor_confidence_cap` 始终成立。
5. 没有设备回执的行动只能显示为建议或模拟，不能显示为完成。

## 五、真实使用反馈与反馈驱动改动

### 已发生的首次体验

2026-08-09，J 在 Mac 浏览器中先体验本地 Replay，随后打开 Render 公网 Replay。体验任务是判断多个 Agent 是否真正参与解释，以及观点是否会随证据周期变化。

J 的原话必须保持逐字一致：

> “这七个agent应该要放到主位，但是现在我们对它的感知不强。”

> “虽然系统会持续播放和更新，但是文字内容好像没变化吧。”

### 查明的问题

- `AgentVoiceRiver` 已实现但没有挂载到首页；
- 旧实现会把不同 Council 周期的角色旧观点混在一起；
- 因此系统虽然在更新，用户却感受不到 Agent 的存在和观点变化。

### 已完成的反馈驱动改动

- 把观点组件挂载到首页；
- 只呈现最新完整周期，不再跨周期拼接；
- 让观点与主视觉使用一致的彩虹映射。

### 第二阶段定位改动（尚待用户复验）

在本轮复赛定位与实现中，公开体验进一步收敛为一个用户可见的 Room Echo Agent，并把受限行动反应放进独立小窗口。这不是 J 已经确认的改动效果，而是从首轮问题继续推导出的设计决策。

首轮问题修复已有自动化验证；“单一 Agent + 行动窗口”尚未由 J 二次体验确认。

### 不能提前填写的结果

J 的公网二次体验仍待完成。当前只能说“真实反馈触发了可核验改动”，不能说“用户已经确认问题解决”，也不能把 J 的体验写成养老用户验证。

**主标题**

|---|---|---|
| 摄像头 | 留下清晰影像 | 隐私负担太重 |

持续感知代理变化 → 解释不确定性 → 选择最轻的反应 → 允许用户纠正。

**建议视觉**

三个极简图标退到浅灰，中央以一条由红、橙、黄、绿、蓝、紫数字组成的“感知—解释—反应”闭环贯穿。

**页脚真值边界**

一个 Agent 的表达，不会把内部 Agent 一致度变成更高的传感置信。

### 第 4 页｜它会反应，也会选择不行动

**主标题**

> 主动性不等于多做事，
> 而是知道何时做最轻的一件事。

**关键边界**

模拟行动不是设备执行；异常模式不是跌倒检测；近中远代理不是完整路径。

**建议视觉**

## 八、4 分钟以内路演讲稿

> 建议语速：每分钟 220—250 个汉字。以下纯讲版约 3 分 30 秒，不在现场完整播放 2 分钟视频；可嵌入 8—10 秒无声产品录屏。若现场必须播放完整视频，应将口述缩短到开场和结尾，确保总时长仍不超过 4 分钟。

### 0:00—0:32｜第 1 页

我从自己 J 开始。我长期在小型空间做 AI 和视觉创作，想感受房间什么时候平静、什么时候流动，却不想让摄像头一直拍着我。这里缺的不是更强的监控，而是一种克制的空间反馈：能感知变化，也敢在证据不足时说不知道。

### 0:32—1:02｜第 2 页

摄像头知道得太多，普通人体传感器通常只给一个状态，聊天助手又只能等待开口。Room Echo 填补中间这层：不识别我是谁，也不描述姿态，只把 Wi-Fi 变化转成活动、遮挡与空间占用、相对纵深三个代理，再解释这些有限证据。

### 1:02—1:42｜第 3 页

改版后，前台只保留一个 Room Echo。左侧回答：我观察到什么、如何理解、还不知道什么、为什么这样反应；底部一次只显示一个行动；右侧保留原有彩色数字推断场，并仍由三个代理信号实时驱动。数字轮廓不是人物影像或姿态。后台多视角和怀疑者只负责反证与审计，不能改测量，也不能因意见一致就提高传感置信。

### 1:42—2:16｜第 4 页

公开 Replay 中，平稳时 Room Echo 保持静默；出现连续变化时继续观察；干扰未排除时明确暂不行动。环境光只在推断场中显示 `SIMULATED PREVIEW`，没有控制真实灯具；轻量确认属于下一 MVP，更不是跌倒检测。主动性不是多做事，而是知道何时只做最轻的一件事。

### 2:16—2:56｜第 5 页

第一次体验时，J 没有说“很酷”，而是指出：“这七个agent应该要放到主位，但是现在我们对它的感知不强。”“虽然系统会持续播放和更新，但是文字内容好像没变化吧。”我们查到组件未挂载且混合不同周期，于是把观点带到首页、只保留最新完整周期。单一 Agent 是随后基于新定位做出的第二阶段收敛，二次体验仍待确认，我们不会提前写成成功。

### 2:56—3:30｜第 6 页

候选版本已部署并完成公网复验，评委可以打开公网 Replay，体验三个代理信号、明确未知、确定性 Mock Council 与 Policy，以及不会突破传感置信上限的 Room Echo；真实 DeepSeek 证据来自与循环 Replay 分开的 gated invoke。Replay 已完成 60 分钟、85 轮、零崩溃；真实住宅、灯具和养老用户仍是下一步。Room Echo Care 将验证这套能力能否进入原居生活。我们想让不使用摄像头的房间，先学会克制地回应。
